# 项目文档结构规范

适用于需要完整文档体系的项目。小型项目可按需裁剪，不必强制六份全写。

---

## 文档体系

| 文件名 | 回答的问题 |
| --- | --- |
| `01_需求分析.md` | 为什么做、解决什么问题、成功标准是什么 |
| `02_技术调研.md` | 备选方案有哪些、为什么选现在这套 |
| `03_技术方案.md` | 当前系统是怎么设计的 |
| `04_实现说明.md` | 在仓库和系统中是如何落地的 |
| `05_测试方案.md` | 如何验证当前方案是对的 |
| `06_部署文档.md` | 如何把当前方案部署起来并运行起来 |

模板文件在 [`templates/`](templates/) 目录，直接复制使用：

```bash
cp docs/templates/03_技术方案.md docs/<your-project>/03_技术方案.md
```

---

## 各文档职责边界

### `01_需求分析.md`

写：项目目标、核心问题、使用场景、里程碑、当前范围、非目标、成功标准。

不写：技术实现、部署细节、方案比较过程。

### `02_技术调研.md`

写：最佳实践参考、候选方案（≤3 种，每种列优缺点）、选型结论、关键权衡。

不写：搜索过程流水账、超过 3 种的发散对比、已淘汰方案详细描述。

要求：结论必须基于可验证资料，只保留仍支撑当前方案的调研结论。

### `03_技术方案.md`

写：总体架构、组件职责、数据流 / 任务流、系统边界、与外部系统的关系。

不写：操作步骤、测试记录、历史方案对比、路线图。

### `04_实现说明.md`

写：已实现能力、模块分工、关键配置关系、关键依赖关系、已实现 / 未实现边界。

不写：代码逐文件罗列、源码导读、大段粘贴配置或代码、操作手册。

### `05_测试方案.md`

写：测试目标、测试范围、验证分层、核心测试项、验收标准、最小回归清单。

不写：某次具体测试经过、某天失败了什么、长篇故障复盘。

### `06_部署文档.md`

写：前置条件、部署步骤、配置项、Secret 要求、健康检查、常见运维动作。

不写：需求背景、技术推导过程、调研比较过程、路线图。

## 更新规则

**触发标准：** 有人按现有文档操作，会得到错误结果，则必须更新。

| 变化类型 | 更新目标 |
| --- | --- |
| 目标或范围变了 | `01_需求分析.md` |
| 技术判断变了 | `02_技术调研.md` |
| 架构边界变了 | `03_技术方案.md` |
| 实现结构变了 | `04_实现说明.md` |
| 验证方式变了 | `05_测试方案.md` |
| 部署步骤或运维方式变了 | `06_部署文档.md` |

过程性事件（临时问题、一次性调试）不触发文档更新。
